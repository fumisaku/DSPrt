### 3-1. Table1 — 競技区分・種別 / ラウンド

#### PRGNO — 進行番号

| 項目 | 内容 |
|------|------|
| TextObject 名 | `PRGNO` |
| データ取得先 | `DS_Status.DS_FLOORs[].DS_PRGRSs[].DS_PrgNo` + `DS_PrgSubNo` |
| 表示形式 | `DS_PrgNo` は **3桁ゼロ埋め**（`int.ToString("D3")`）で表示。枝番が `"0"` または `"1"` の場合は進行番号のみ。それ以外は `進行番号-枝番` の形式 |
| 例 | `"003"` / `"003-2"` |

#### KubunName — 区分名

| 項目 | 内容 |
|------|------|
| TextObject 名 | `KubunName` |
| 構成要素と連結ルール | 下表参照 |

**KubunName 構成ルール（スペース区切りで連結）:**

| 要素 | 常に表示 | 条件 | データ取得先 |
|------|---------|------|-------------|
| 区分番号 | ✅ | **2桁ゼロ埋め**（`int.ToString("D2")`）で表示 | `DA_Master.DB_KUBUNs[].DB_KbnNo` |
| 区分コード | ✅ | 空でない場合 | `DA_Master.DB_KUBUNs[].DB_KbnCd` |
| 区分名 | ✅ | 空でない場合 | `DA_Master.DB_KUBUNs[].DB_KbnDsipName`（なければ `DB_KbnDispName` → `DB_KbnName`） |
| 種目グループ名 | 条件付き | **同区分・ラウンドに種目グループが2つ以上ある場合のみ**表示 | `DA_Master.DB_KUBUNs[].DC_ROUNDs[].DD_DGRPs[].DD_DGrpName` |
| フロア名 | 条件付き | **競技会にフロアが2つ以上ある場合のみ**表示（`"X フロア"` 形式） | `DS_Status.DS_FLOORs[].DS_FlrCd` |

**例:**
- フロア1つ・種目グループ1つ: `01 PD PDグランプリカップ スタンダード`
- フロア2つ・種目グループ1つ: `01 PD PDグランプリカップ スタンダード A フロア`
- フロア1つ・種目グループ2つ: `01 PD PDグランプリカップ スタンダード スタンダード5種目`

| 項目 | 内容 |
|------|------|
| TextObject 名 | `Round1` 〜 `Round7` |

## 4. データ行（DataBand）— ヒート別出場者

DataBand 内のヒート行テーブル（Table4〜Table9）は最大6行。

### 表示可否

| 条件 | 動作 |
|------|------|
| そのインデックスに対応するヒートが存在する | テーブルを表示（`Visible = true`） |
| 対応するヒートが存在しない | テーブルを非表示（`Visible = false`） |

> 例: 4ヒートの場合 → Table4〜Table7 を表示、Table8・Table9 を非表示

### HeatNoX — ヒート番号

| 項目 | 内容 |
|------|------|
| TextObject 名 | `HeatNo1` 〜 `HeatNo6` |
| データ取得先 | `DS_PRGHEATs[].DS_HeatNo`（HeatId → HeatNo のマッピングで解決） |

### NoXX_YY — 背番号 / NameXX_YY — 選手名

| 項目 | 内容 |
|------|------|
| TextObject 名（背番号） | `No01_01`〜`No06_20`（行番号_列番号、2桁ゼロ埋め） |
| TextObject 名（選手名） | `Name01_01`〜`Name06_20` |
| 背番号取得先 | `DS_PRGRSs[].PlayerAssignments[].PlayerNo` |
| ヒート割当 | `PlayerAssignments[].AssignedHeatIds[0]`（先頭ヒートID）で `DS_HeatNo` を解決 |

| 並び順 | 背番号の数値昇順 |
| 1ヒート20組以上の場合 | 次の行（例: 1ヒートが21組 → Table4 に21〜20組目、Table5 に残り）に分割。最大6行まで |
| 対応する選手がいない列 | 空文字 |

## 6. PR_PRINT 電文の data フィールド仕様

`PLAYER_NOTICE_HORIZONTAL_A4` の `PR_PRINT.data` は以下の形式:

```json
{
  "KbnNo":  "1",
  "RndNo":  "1",
  "DGrpNo": ""
}
```

| フィールド | 型 | 必須 | 説明 |
|-----------|---|------|------|
| `KbnNo` | string | ✅ | 区分番号。`DA_Master.DB_KUBUNs[].DB_KbnNo` と一致するもの |
| `RndNo` | string | ✅ | ラウンド番号。`DA_Master.DC_ROUNDs[].DC_RndNo` と一致するもの |
| `DGrpNo` | string | — | 種目グループ番号（省略 or `""` の場合は最初のグループを使用） |

> DA_Master / DS_Status はキャッシュから参照するため `data` に含める必要はない。

### ⚠️ テストデータ JSON のキー名は必ず小文字

`MainWindow.xaml.cs` の `TryGetProperty` は**大文字小文字を区別する**。
テストデータ JSON のトップレベルキーは以下の小文字で統一すること：

```json
{
  "jobId":    "...",
  "layoutId": "...",
  "copies":   1,
  "data": {
    "KbnNo": "...",
    "RndNo": "...",
    "DGrpNo": ""
  }
}
```

| NG（大文字） | OK（小文字） |
|------------|------------|
| `"JobId"` | `"jobId"` |
| `"LayoutId"` | `"layoutId"` |
| `"Copies"` | `"copies"` |
| `"Data"` | `"data"` |

> `data` 内の `KbnNo` / `RndNo` / `DGrpNo` はバインドメソッド側で `JObject.Parse` して読むため、こちらは大文字小文字を問わない。

## 7. 実装上の注意

### フォントサイズ補正（印刷時）

`PrintDocument.PrintPage` の `Graphics` は `PageUnit = Display`（100dpi 論理ピクセル）がデフォルト。
FastReport の `TextObject` は `IsPrinting=true`（印刷時デフォルト）のとき **フォントサイズを scaleX でスケールしない**。
その結果、レイアウト座標は `scaleX` 倍されるのにフォントサイズだけ据え置きとなり、相対的に小さく見える。

対処: `PreparedPages.GetPage(i)` で取得した `ReportPage` の全 `TextObject` に対して `Draw()` の **前に** フォントサイズを補正する。

```csharp
// PrintDirect() 内 — page.Draw() の前に実行
AdjustFontSizesForPrinting(page, 1.2f);

// AdjustFontsInObject() が TextObject を再帰探索してフォントサイズを scale 倍に補正
private void AdjustFontSizesForPrinting(FastReport.ReportPage page, float scaleX)
{
    int count = 0;
    AdjustFontsInObject(page, scaleX, ref count);
}

private static void AdjustFontsInObject(object obj, float scaleX, ref int count)
{
    if (obj is FastReport.TextObject txt)
    {
        txt.Font = new Font(txt.Font.FontFamily, txt.Font.Size * scaleX,
                            txt.Font.Style, GraphicsUnit.Point);
        count++;
    }
    if (obj is FastReport.IParent parent)
    {
        var children = new FastReport.ObjectCollection();
        parent.GetChildObjects(children);
        foreach (FastReport.Base child in children)
            AdjustFontsInObject(child, scaleX, ref count);
    }
}
```

| パラメーター | 値 | 理由 |
|------------|---|------|
| `scaleX` | **`1.2f`** | `logicalDpi(100) / 96f ≈ 1.042` では変化が小さすぎ体感できないため、実機確認で適正と判断した補正値 `1.2` を使用 |

> **注意**: `report.Pages`（デザイン時ページ）の TextObject を補正しても `Prepare()` で上書きされるため無効。
> 補正は `PreparedPages.GetPage(i)` 取得後・`page.Draw()` 呼び出し前に実施する。

### TextObject への値セット

FastReport の `TextObject` は `report.FindObject(name)` で取得し、`Prepare()` 前に `Text` および `FillColor` を直接書き換える。`DataBand` のバインドは使用しない。

```csharp
// Text 設定
var obj = report.FindObject("PRGNO") as FastReport.TextObject;
if (obj != null) obj.Text = "3";

// 背景色設定

obj.FillColor = System.Drawing.Color.Transparent;  // 通常
```

未使用ヒート行（Table4〜Table9）は `Visible = false` で非表示にする。

```csharp
var tbl = report.FindObject("Table8") as FastReport.Table.TableObject;
if (tbl != null) tbl.Visible = false;
```

すべての `SetTextObject` / `SetTextObjectFill` / `SetTableVisible` は **`report.Prepare()` の前**に呼ぶこと。`Prepare()` 後の変更は描画に反映されない。

### 罫線（Border.Lines）の動的制御

#### 原則

frx テンプレートで罫線を「常に表示」に設定しておくと、**データがない列・行にも罫線枠が印刷される**。
これを防ぐため、罫線が可変となる TextObject は frx 上では **`Border.Lines="None"`（罫線なし）をデフォルト** とし、C# コードから実行時に `BorderLines.All` を必要な箇所だけセットする設計を採る。

#### 適用する場面

| 状況 | frx デフォルト | コードでのセット条件 |
|------|--------------|-------------------|
| データが入る行（選手あり） vs 空行 | `None` | `hasData ? All : None` |
| 使用する種目列（danceCount 以内）vs 余った列 | `None` | `di < danceCount ? All : None` |
| 上記の組み合わせ（行×列） | `None` | `hasData && di < danceCount ? All : None` |

#### 実装パターン

`SetTextObjectDirect` を使い、Text と Border.Lines を同時に設定する：

```csharp
// 例: データ行 × 種目列の罫線制御
for (int di = 0; di < 10; di++)
{
    var colBorder = (hasData && di < danceCount)
        ? FastReport.BorderLines.All
        : FastReport.BorderLines.None;
    SetTextObjectDirect(report, $"VR{rr}_C{di + 3:D2}", heatNos[di], colBorder);
}

// 例: 列ヘッダー行の罫線制御
bool hasDance = i <= danceCount;
SetTextObjectDirect(report, $"D{i:D2}", hasDance ? dsCodes[i - 1] : "",
    hasDance ? FastReport.BorderLines.All : FastReport.BorderLines.None);
```

#### 注意点

- `SetTextObject`（Text のみ設定）と `SetTextObjectDirect`（Text + Border.Lines 設定）は役割が異なる。罫線制御が必要な列は必ず `SetTextObjectDirect` を使うこと。
- **複数ページ対応でページ複製（`DuplicatePageInReportXml`）を行う場合**、再ロード後にヘッダー TextObject を再セットするブロックがある。そのブロックでも同じ Border.Lines セットロジックを適用すること（抜け漏れると1ページ目と2ページ目以降で罫線が異なる結果になる）。
- `Border.Lines` の設定も `Prepare()` 前に完了させること。

## 8. セル内文字の自動縮小（AutoShrink）

### 概要

氏名・フリガナ・所属など、データ長が可変な列では、テキストがセル幅を超えた場合に**フォントサイズを自動縮小**して収める。
FastReport の `AutoShrink` / `AutoShrinkMinSize` プロパティを C# コードから設定する（frx への記述も可能だが、ページ複製時の再セット漏れを防ぐためコード管理が推奨）。

### C# での設定方法

```csharp
obj.AutoShrink        = FastReport.AutoShrinkMode.FontSize;  // フォントサイズ縮小モード
obj.AutoShrinkMinSize = 6f;   // 最小フォントサイズ（単位: pt）
```

`SetTextObjectDirectEx` ヘルパーを使うと Text・Border.Lines・AutoShrink を一括設定できる:

```csharp
private static void SetTextObjectDirectEx(Report report, string name, string text,
    FastReport.BorderLines borderLines, bool autoShrink)
{
    var obj = report.FindObject(name) as FastReport.TextObject;
    if (obj == null) return;
    obj.Text              = text;
    obj.Border.Lines      = borderLines;
    obj.AutoShrink        = autoShrink ? FastReport.AutoShrinkMode.FontSize
                                       : FastReport.AutoShrinkMode.None;
    obj.AutoShrinkMinSize = autoShrink ? 6f : obj.AutoShrinkMinSize;
}
```

### AutoShrinkMode の種類

| 値 | 動作 |
|----|------|
| `AutoShrinkMode.None` | 縮小しない（デフォルト） |
| `AutoShrinkMode.FontSize` | テキストが収まるまでフォントサイズを縮小する |
| `AutoShrinkMode.Width` | テキストが収まるまで文字間隔を縮小する |

> **推奨**: `FontSize` モードを使うこと。`Width` は字形が潰れて読みにくくなる。

### 最小フォントサイズ

| 用途 | 推奨最小サイズ |
|------|--------------|
| 氏名・フリガナ・所属 | **6pt** |
| ヒート番号など数値 | AutoShrink 不要（固定幅データ） |

> 6pt 以下になるとプリント出力でほぼ判読不能になるため、6pt を下限として設定する。

### 適用対象（帳票別）

| 帳票 | AutoShrink を適用する列 |
|------|----------------------|
| 決勝進出者名簿 | C02（氏名）・C03（フリガナ）・C04（所属）の L行・P行すべて |

- `AutoShrink` は `report.Prepare()` の**前**に設定すること。`Prepare()` 後は反映されない。

## 9. 複数ページ対応（DuplicatePageInReportXml）

### 概要

FastReport の `DataBand` による自動改ページではなく、**固定行数の frx テンプレートをページ単位で複製**することで複数ページを実現する方式。
1ページに収まるデータ数の上限（例: 決勝進出者名簿 = 10組/ページ）を超えた場合に適用する。

### 仕組み

```
1. report.SaveToString()  → frx XML 文字列を取得
2. DuplicatePageInReportXml(xml, pageCount) → <ReportPage> ブロックを必要ページ数分複製
   ・複製ページの全 TextObject 名に "_P02" / "_P03" ... のサフィックスを付与（名前重複防止）
3. report.LoadFromString(newXml) → 複製済み XML で Report を再ロード
4. 再ロード後にヘッダー TextObject を再セット（再ロードで初期値に戻るため）
5. 各ページのデータ行に suffix 付きの TextObject 名でデータをセット
```

### TextObject 名のサフィックス規則

| ページ | サフィックス | TextObject 名の例 |
|--------|------------|-----------------|
| 1ページ目 | なし（`""`） | `DL_01_C01` |
| 2ページ目 | `_P02` | `DL_01_C01_P02` |
| 3ページ目 | `_P03` | `DL_01_C01_P03` |

> **注意**: 帳票によってサフィックスの付け方が異なる。決勝進出者名簿では `pg==0` は `""`, `pg>=1` は `_P{pg+1:D2}` で計算する。

### ページあたり最大行数（帳票別）

| 帳票 | 定数名 | 1ページ最大 |
|------|--------|------------|
| 決勝進出者名簿 | `PairsPerPage = 10` | 10組（L行+P行=20行） |
| 出場者ヒート表_縦 | `RowsPerPage = 30` | 30名 |

### 再ロード後の必須再セット項目

`report.LoadFromString(newXml)` 後は **すべての TextObject が初期値（frx の設定値）に戻る**。
以下を再セットすること:

| 再セット対象 | 理由 |
|------------|------|
| ヘッダー TextObject（Title・PRGNO・KubunName・Round1〜7 等） | ロードで初期値に戻る |
| Table3 の DS1〜5 / DC1〜5（背景色含む） | ロードで初期値に戻る |
| 列ヘッダー行の `DH_C06〜C10`（種目コード・Border.Lines） | ロードで初期値に戻る |
| 各データ行の AutoShrink 設定 | ロードで初期値に戻る |

### ページ数の計算式

```csharp
int pageCount = Math.Max(1, (int)Math.Ceiling((double)dataCount / itemsPerPage));
```

### 実装の流れ（コード骨格）

```csharp
int pageCount = Math.Max(1, (int)Math.Ceiling((double)playerRows.Count / PairsPerPage));

if (pageCount > 1)
{
    string origXml = report.SaveToString();
    string? newXml = DuplicatePageInReportXml(origXml, pageCount);
    if (newXml != null)
    {
        report.LoadFromString(newXml);
        // ── 再ロード後にヘッダー・種目列を再セット ──
        SetTextObject(report, "Title",   "決勝進出者名簿");
        // ... (省略) ...
    }
}

// 各ページのデータをセット
for (int pg = 0; pg < pageCount; pg++)
{
    string suffix = pg == 0 ? "" : $"_P{pg + 1:D2}";
    SetFinalEntryPageRows(report, playerRows, pg, PairsPerPage, ..., suffix);
}
```

### frx テンプレート設計のポイント

- frx は **1ページ分のみ**設計する。複数ページはコードで動的に複製する。
- すべての TextObject に **一意な名前**を付けること（サフィックス付与の前提）。
- `PageFooterBand` の `[Page#] / [TotalPages#]` 変数はページ複製後も各ページで正しく表示される（FastReport が自動処理）。

## 10. ページフッター — ページ番号表示

### FastReport 組み込み変数を使ったページ番号

帳票に複数ページが存在する場合、どのページを見ているか分かるよう **フッター右下にページ番号を表示**する。
FastReport の組み込み変数を frx の `Text` に直接書くだけで自動展開される（**C# コードの変更は不要**）。

```xml
<!-- PageFooterBand 内に追加 -->
<TextObject Name="PageNo"
  Left="817.56" Top="9.45" Width="192.51" Height="18.9"
  Text="[Page#] / [TotalPages#] Page"
  HorzAlign="Right" VertAlign="Center"
  Font="MS UI Gothic, 9pt"/>
```

#### 使用する組み込み変数

| 変数 | 意味 | 表示例 |
|------|------|--------|
| `[Page#]` | 現在のページ番号（1始まり） | `1` |
| `[TotalPages#]` | 総ページ数 | `2` |

#### 表示例

```
1 / 2 Page
2 / 2 Page
```

#### 採用理由と注意点

- **C# コード変更なし**: frx の `Text` プロパティに変数名を書くだけで動作する。`SetTextObject` でのセットは不要。
- **複数ページ対応（DuplicatePageInReportXml）でも有効**: `DuplicatePageInReportXml` で複製したページにも同じ TextObject がコピーされるため、全ページで正しいページ番号が表示される。
- **配置基準（横向き A4 の場合）**:
  ページ幅 1047.06pt のうち右端余白 37.8pt を差し引いた `Left=817.56`、`Width=192.51`（右端揃え）を目安とする。

|---|------------|------|
| 1 | **データがない行の罫線** | データ行の全 TextObject を `Border.Lines="None"` にし、コード側で `hasData` 判定してセット |

## 10. テストデータ作成時の注意

### ⚠️ RndNo は DS_Status と必ず一致させること

PR_PRINT 電文の `data.RndNo` はバインドメソッド内で **DS_Status の `DS_RndNo` と文字列一致** で照合される。
値が異なると対象の `DS_PRGRS` が見つからず、データが**一切表示されない**（ヘッダーも空になる）。

```
// バインドメソッド内の照合箇所
if (p["DS_RndNo"]?.ToString() != rndNo) continue;  // ← ここで弾かれる
```

#### チェック手順

| ファイル | 確認するキー | 値の例 |
|---------|------------|--------|
| `PR_PRINT_xxx_テスト.json` | `data.RndNo` | `"4"` |
| `DS_Status_xxx.json` | `DS_FLOORs[].DS_PRGRSs[].DS_RndNo` | `"4"` ← 一致必須 |
| `DA_Master_xxx.json` | `DB_KUBUNs[].DC_ROUNDs[].DC_RndNo` | `"4"` ← 一致必須 |

**よくあるミス:**
- 6組テストデータで `RndNo: "7"` と書いたが DS_Status には `DS_RndNo: "4"` しか存在せず全データが空表示になった。
- `RndNo` を変更したとき DA_Master 側の `DC_RndNo` との一致も確認すること。

## データ取得パス

### 選手ヒート番号解決フロー

```
1. DS_Status.DS_FLOORs[].DS_PRGRSs[] から KbnNo+RndNo+DGrpNo で対象 PRGRS を特定
2. DS_PRGDANCEs[] を DS_DncNo 昇順でソート → 種目インデックスと DA_Master 種目順を対応

```

## 実装上の注意

- frx の DataBand に `DataSource="PlayerHeatPage"` を設定しており、FastReport が DataTable 行数分 DataBand を繰り返すことで自動改ページされる。
- PageHeader の `D01`〜`D10`（列ヘッダー）は `SetTextObjectDirect` で Text と Border.Lines を同時にセット（Prepare 前）。
- 種目数が10未満の場合、余った `D(n+1)`〜`D10` の TextObject は空文字＋`Border.Lines=None`＋Transparent に設定する。
- `AssignedHeatIds` の各要素は種目インデックス順（di=0=種目1, di=1=種目2…）で割り当てられることを前提とする。種目数と AssignedHeatIds の要素数が異なる場合は `[0]`（先頭）にフォールバックする。
- フォントサイズ補正（AdjustFontSizesForPrinting, scaleX=1.2f）は他帳票と同様に PrintDirect で適用される。

### 罫線の動的制御（本帳票での実装）

frx のデフォルト設定と C# コードの役割分担：

| TextObject | frx デフォルト | コードでのセット条件 |
|-----------|--------------|-------------------|
| `VRxx_C01`（背番号）| `All` | `hasData ? All : None`（`SetPageDataRows` 内） |
| `VRxx_C02`（選手名）| `All` | `hasData ? All : None`（`SetPageDataRows` 内） |
| `VRxx_C03〜C12`（ヒート番号）| **`None`** | `hasData && di < danceCount ? All : None` |
| `D01〜D10`（列ヘッダー）| **`None`** | `i <= danceCount ? All : None` |

**実装の根拠**：競技種目数は競技種別によって異なる（例：ワルツのみ1種目、WTVWSFQ で7種目）。
種目数を超えた右側の列は常に空白となるため、罫線があると視覚的に不自然な枠が印刷される。
frx をデフォルト `None` にしておくことで、コードが種目数を知らない状態でも誤って罫線が出ることを防ぐ。

- `・` = 中黒（U+30FB）
- `／` = 全角スラッシュ（U+FF0F）

### 並び順

1. 種目: `DA_Master.DE_DANCEs[].DE_DncNo` の昇順
2. ヒート: `DS_PRGHEATs[].DS_HeatNo` の昇順
3. 同一ヒート内選手: `PlayerNo` の数値昇順

---

## データ取得パス

### 選手情報

| フィールド | パス | 用途 |
|----------|------|------|
| 背番号 | `PlayerAssignments[].PlayerNo` | 表示・ソート |
| L選手名 | `DM_MEMBERs[].DM_MASTERs[].DM_LDispName` | ソロ行表示 |
| P選手名 | `DM_MEMBERs[].DM_MASTERs[].DM_PDispName` | ソロ行表示 |
| L所属 | `DM_MASTERs[].DM_LCtry`（なければ `DM_Ctry` にフォールバック） | ソロ行表示 |
| P所属 | `DM_MASTERs[].DM_PCtry`（なければ `DM_Ctry` にフォールバック） | ソロ行表示 |

### ヒート番号解決フロー

```
1. DS_PRGDANCEs[] を DS_DncNo 昇順でソート → 種目インデックスと DA_Master 種目順を対応
2. 種目 di の DS_PRGHEATs[] から { DS_HeatId → DS_HeatNo } マップを生成
3. PlayerAssignments[].AssignedHeatIds[di] でヒートIDを解決 → HeatNo を取得
   ※ AssignedHeatIds の要素数が種目数より少ない場合は [0] を代替使用
4. 種目 di × ヒート番号 → 選手番号リストを構築（SortedDictionary<HeatNo, List<PlayerNo>>）
```

- 最大40行に収まらない場合（種目数×ヒート数の合計が40行超）は40行で打ち切られる。通常の決勝（5種目・各1〜6ヒート程度）では問題ない。

- `DM_LCtry` / `DM_PCtry` が存在しない旧データの場合は `DM_Ctry`（カップル共通所属）にフォールバックする。
- ヒート行の背番号は数値変換可能な場合は整数表示（ゼロ埋めなし）、変換不可の場合は文字列そのまま。
